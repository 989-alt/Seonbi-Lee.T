# 사주 · 타로 질문 카탈로그 & Claude API(Sonnet 5.5) 연동 설계

> `saju-tarot-logic.md`(계산 로직)의 후속 문서. **어떤 질문에 답할 수 있는지**, 각 질문에 **사주/타로의 어떤 요소를 근거로 쓰는지**, 그리고 **Sonnet 5.5로 답할 때의 비용과 개인정보 원칙**을 정리한다.

---

## 0. 공통 원칙

1. **원본 개인정보는 API로 보내지 않는다.** 생년월일시·성별·상대방 생일은 브라우저에서만 계산하고, Claude에는 계산된 *특징값*(간지·오행 수·십신·대운 간지 목록 등)만 보낸다. 특징값에서 생년월일을 역산할 수 없다(같은 8글자를 가진 날짜는 60년마다 반복되고, 시각·성별도 보내지 않음).
2. **질문 = (영역 × 기간)** 으로 구조화한다. 자유 텍스트는 보조로만 받는다.
3. 답하지 않는 영역: 질병 진단·수명·사망 시기, 특정 투자 종목, 합격·당락 단정, **특정 학생·타인에 대한 점**, 이혼·불륜 단정.

# Part A. 사주로 답할 수 있는 질문

## A1. 기간 축 — "언제의 운인가"

| 기간 | 근거 | 질문 예 |
|---|---|---|
| **평생운(총운)** | 원국 전체: 격국(월지 중심), 신강/신약, 용신, 오행 균형, 대운의 전체 흐름 | "제 사주 전체적으로 어때요?", "타고난 그릇은?" |
| **초년·청년·중년·말년** | 궁성론 — 연주=초년(~20대)·조상, 월주=청년(20~40)·부모/사회, 일주=중년(40~60)·나/배우자, 시주=말년(60~)·자녀 | "제 말년운은?", "중년에 잘 풀려요?" |
| **과거 / 현재 / 미래** | 지난 대운 · 현재 대운 · 다음 대운 (또는 작년·올해·내년 세운) | "지난 몇 년이 왜 힘들었을까?", "앞으로는?" |
| **10년 / 20년 / 30년** | 대운 1개 = 10년 → 현재부터 대운 1·2·3개. 각 대운 천간·지지의 십신 + 원국과의 합충 + 12운성 + 용신 부합 여부 | "앞으로 10년 흐름은?", "30년 인생 그래프" |
| **올해(신년운세)** | 세운(올해 간지)과 원국·현재 대운의 관계 | "2027년 운세" |
| **이번 달 / 월별 12개월** | 월운(절기 기준 월주) | "올해 몇 월이 제일 좋아요?" |
| **오늘 / 이번 주** | 일진 | "오늘의 운세" |
| **특정 날짜** | 그날 일진과 원국 관계(택일) | "다음 주 공개수업 날 운은?" |

**인생 그래프** (인기 기능): 대운별 점수를 0~100세 라인 차트로.
`대운 점수 = 50 + 용신/희신 부합(+20) − 기신(−15) + 일지·월지와 합(+10) − 충(−10) + 12운성 보정(건록·제왕 +10 / 병·사·절 −5)`

## A2. 영역 축 — "무엇에 대한 운인가"

| 영역 | 사주에서 보는 것 | 세부 질문 예 |
|---|---|---|
| **성격·기질** | 일간(10종), 월지, 십신 분포, 오행 과다/부족 | 장단점, 스트레스 받는 상황, 나를 살리는 습관 |
| **연애운** | 일지(배우자궁), 도화·홍염살, 배우자성*, 세운에서 일지 합/도화 들어오는 해 | 연애 성향, 인연 들어오는 시기, 끌리는 상대 유형, 짝사랑 |
| **결혼운** | 배우자궁 안정성(일지 합·충·형), 배우자성 강약, 대운·세운의 배우자성 | 결혼 시기, 배우자 성향, 결혼 후 생활 |
| **궁합** | 두 사람 일간 합(甲己 등), 일지 합·충·원진, 오행 상호 보완, 띠 궁합(삼합·육합·원진) | 연인·부부·동료 궁합 |
| **재물운** | 재성 유무·강약, 식상생재 구조, 재고(辰戌丑未), 신강해야 재를 감당 | 돈 버는 방식(월급형/사업형), 돈 들어오는 시기, 지출 주의 시기 |
| **직업·적성** | 십신 중심 — 관성(조직·공직), 인성(교육·연구), 식상(강의·창작), 재성(사업·관리), 비겁(독립·경쟁) | 맞는 직업, 이직·전직 시기 |
| **교사 특화** | 관성(승진·보직), 인성(연수·대학원), 식상(수업·표현), 역마(전보·이동) | 승진/보직/전보운, 담임 vs 비담임 적성, 수업 스타일 |
| **학업·시험운** | 인성 강약, 문창귀인·학당귀인·화개, 관인상생 구조, 세운의 인성 | 공부 스타일, 시험·자격증 좋은 해, 대학원 |
| **명예·승진** | 관성, 관인상생, 정관의 안정 | 인정받는 시기, 리더 역할 |
| **대인관계·인복** | 비겁(동료), 인성(윗사람), 식상(후배·학생), 관성(상사), 천을귀인 | 귀인 유형, 조심할 관계 |
| **가족운** | 부모=인성·연월주, 형제=비겁, 자녀=식상/관성·시주 | 부모와의 관계, 자녀운 |
| **건강(생활 조언)** | 오행↔장부 대응: 木 간·담, 火 심장·소장, 土 비·위, 金 폐·대장, 水 신장·방광. 부족/과다 오행 | "체력 관리 포인트" 수준만 (진단 금지) |
| **이사·이동·해외** | 역마살, 일지·월지 충, 대운 전환기 | 이사·해외연수 시기 |
| **구설·갈등 주의** | 상관견관, 형살, 원진 | 말조심 시기 |
| **사업·투자 성향** | 재성·식상·비겁 구조 | 사업 체질인가 (종목 추천 금지) |
| **행운 요소** | 용신 오행 → 색·숫자·방향·계절·음식·활동 | 행운의 색, 좋은 방향 |

\* **배우자성**: 전통적으로 남자는 재성, 여자는 관성을 배우자로 본다. 성별을 묻지 않는 것이 기본이므로 **기본값은 일지(배우자궁)·도화·합 중심의 현대식 해석**, 성별 선택 시에만 전통 해석을 추가. 성별은 브라우저에서만 쓰고 전송하지 않는다.

**궁합의 개인정보 처리**: 상대 생년월일은 제3자 정보다. ① 상대의 **띠 또는 일간만 선택**하게 하는 방식이 기본, ② 생년월일 입력 시에도 브라우저 계산 후 특징값만 전송·저장 금지, 화면에 "상대방 동의 없이 입력하지 마세요" 고지.

## A4. 질문 → 필요 데이터 → 전송 특징값

| 질문 유형 | 필요한 입력 | Claude에 보내는 것 (예시) |
|---|---|---|
| 성격·평생운 | 생년월일(+시각) | `원국 8자, 오행수, 십신 분포, 신강약, 용신, 신살 목록` |
| 대운 10/20/30년 | + 성별(대운 방향) | `대운 간지 목록과 시작 나이, 각 대운 십신·합충·점수` (성별 자체는 미전송) |
| 연·월·일운 | 생년월일 | `원국 요약 + 대상 기간 간지 + 관계 판정` |
| 궁합 | 내 정보 + 상대 띠/일간 | `양쪽 일간·일지·띠, 합충 판정, 오행 보완표` |
| 택일 | 생년월일 + 기간 | Claude 불필요(규칙 계산) → 결과 설명만 템플릿 |

**계산은 코드, 말은 Claude.** 합충·용신·점수 같은 판정은 전부 코드로 결정해 넘기고, Claude는 그 판정을 자연스러운 상담 문장으로 풀어 쓰는 역할만 맡는다. (같은 사주에 다른 답이 나오는 "환각"을 막는 핵심)

## B3. 해석 기법(방법)

| 기법 | 내용 | 구현 |
|---|---|---|
| 정/역방향 | 역방향 = 막힘·내면화·과잉. 켜기/끄기 옵션 | 카드별 `reversed` 확률 |
| 위치 의미 | 같은 카드라도 위치(장애/조언/결과)에 따라 해석이 달라짐 | 스프레드 정의에 position 설명 포함 |
| 메이저 비율 | 메이저가 많으면 큰 흐름·운명적 시기 | 집계 규칙 |
| 슈트 분포 | 많이 나온 슈트 = 지금의 핵심 영역(불·물·공기·흙) | 집계 규칙 |
| 숫자 반복 | 같은 숫자 반복 시 그 숫자의 의미 강조 | 집계 규칙 |
| 원소 품위 | 인접 카드 원소가 우호(불–공기, 물–흙)/대립(불–물, 공기–흙)하면 의미가 강해지거나 약해짐 | 인접 쌍 판정 |
| 코트카드 = 인물 | Page·Knight·Queen·King은 주변 인물이나 내 태도 | 해석 문장 분기 |
| 시그니피케이터 | 질문자를 대표하는 카드를 먼저 정함(주로 코트카드) | 선택 기능 |
| 점프 카드 | 셔플 중 튀어나온 카드 = 추가 메시지 | 셔플 애니메이션 중 낮은 확률로 이벤트 |
| 바닥 카드 | 덱 맨 아래 카드 = 숨은 영향 | 셔플 후 마지막 카드 |
| 퀸테센스 | 펼친 카드 숫자 합 → 22 이하로 축약 → 메이저 카드 = 전체 요약 | 규칙 계산 |
| 예/아니오 규칙 | 정방향=예 경향, 역방향=아니오 경향, 일부 카드(탑·달 등)는 "보류" | 카드별 `yesNo` 값 |
| 타이밍 추정 | 슈트별 시간 단위(완드=일·주, 컵=주·월, 소드=일, 펜타클=월·년) + 숫자 | 유파마다 달라 "참고"로만 표기 |
| 버스 카드(생일 카드) | 월+일+연도 합 → 22 이하로 축약 → 타고난 메이저 카드. 예) 1990-07-15 → 2012 → 5 = 교황 | 브라우저 계산(생일 미전송) |
| 올해의 카드 | 생월+생일+올해 연도 합 → 축약 | 브라우저 계산 |
| 질문 다듬기 | "될까요?"보다 "어떻게 하면 ~할 수 있을까요?" 같은 열린 질문을 권장 | 질문 입력창 예시 문구 |

## B4. 사주 × 타로 결합 메뉴
- **"내 사주로 고른 카드"**: 용신 오행에 해당하는 슈트에서 오늘의 조언 카드 1장
- **"올해의 운세 세트"**: 사주 세운 해석 + 연간 타로 12장

# Part C. Claude API 연동 (Sonnet 5.5)

## C1. 역할 분담
| 기능 | 처리 방식 | 이유 |
|---|---|---|
| 오늘/주간/띠별 운세, 카드 기본 문장 | **사전 생성** (Batch API, 50% 할인) → DB 저장 | 개인화가 필요 없어 비용이 고정되고, 사용자 데이터가 전송되지 않음 |
| 주제 상담(연애·재물 등), 대운 해석, 스프레드 종합 해석, 자유 질문 | **실시간 호출** (Sonnet 5.5) | 특징값 조합이 사람마다 달라 사전 생성 불가 |
| 합충·용신·점수·셔플 | **코드** | 결정론적이어야 함 |

## C2. 요청 설계
- 모델 `claude-sonnet-5-5`. effort는 `low`(짧은 답) ~ `medium`(평생운·켈틱 크로스). 해석 규칙은 **고정 시스템 프롬프트 + 프롬프트 캐싱**(약 3,500토큰).
- 사용자 메시지에는 **특징값 JSON + 질문 유형 + (선택) 200자 이내 자유 질문**만 넣는다.
- 자유 질문은 전송 전에 전화번호·이메일·주민번호 패턴을 제거한다. 입력창에는 "이름·학생 정보는 적지 마세요"라고 안내한다.
- 출력 길이 상한: 짧은 답 500자, 중간 1,200자, 긴 답 2,500자.
- 거절 대비: 서버 측 폴백(`fallbacks: "default"`, 베타 헤더) 적용. 금지 영역 질문은 코드에서 먼저 걸러 정중한 고정 문구로 응답한다.
- API 키는 서버(Route Handler)에만 둔다. 하루 1인 N회 제한(기존 `src/lib/rateLimit.ts`)을 걸고, 콘솔에서 월 지출 한도를 설정한다.
- 질문·답변 원문은 저장하지 않고 이용 횟수와 질문 유형만 집계한다.

## C3. 비용 (Sonnet 5.5: 입력 $2 / 출력 $10 / 캐시 읽기 $0.10 per 1M 토큰, 1달러 = 1,400원 가정)

**1회 비용 (캐시 적중 ~ 미적중)**

| 답변 유형 | 입력(가변) | 출력(+사고) | 1회 비용 |
|---|---|---|---|
| 짧은 답 (오늘·예/아니오·원카드 상담) | 400 | 500 (+200) | 약 11 ~ 23원 |
| 중간 (연애·재물·직업 등 주제 상담, 3~7장) | 700 | 1,200 (+400) | 약 25 ~ 37원 |
| 긴 답 (평생운·대운 30년·켈틱 크로스·연간 12장) | 1,200 | 2,500 (+800) | 약 50 ~ 62원 |

**월 비용** (짧은 답 60%, 중간 30%, 긴 답 10%로 섞인다고 가정하면 1회 평균 약 19 ~ 31원)

| 실시간 이용량 | 월 비용 |
|---|---|
| 하루 50회 (월 1,500회) | 약 2.9 ~ 4.7만원 |
| 하루 300회 (월 9,000회) | 약 17 ~ 28만원 |
| 하루 1,000회 (월 3만회) | 약 58 ~ 93만원 |

**사전 생성 비용 (Batch API, 이용량과 무관)**
- 일간 10종 × 매일 오늘의 운세: 월 약 3,200원
- 월간 운세 일간 10종: 월 약 140원
- 타로 156개 문장(정·역방향) × 6개 주제: 1회 약 8,000원

**비용 조절 레버** (영향이 큰 순서)
1. 출력 길이: 비용의 약 80%가 출력이다. 답변을 절반으로 줄이면 비용도 거의 절반이 된다.
2. 긴 답(평생운·켈틱 크로스)은 하루 1회로 제한한다.
3. 같은 특징값과 같은 질문 유형은 결과를 재사용한다. 저장하더라도 원문이 아닌 *특징값 해시*를 키로 쓴다.
